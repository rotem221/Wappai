# Conversation deletion and image-only Pip creation — 2026-11-04

## Delivered

- iOS conversation rows expose an accessible options menu with destructive confirmation. Active conversations cannot be deleted during a running response. Deletion removes Hub messages, replay events, idempotency records and cached agent state. The last deletion creates one empty usable conversation; other conversations remain intact. Connected iOS/Web clients refresh from a `session.deleted` event. Backups and provider-managed history are separate.
- Selecting a Photos/library image or file displays the reference and one preview-generation confirmation, without name/description fields. The server supplies the name and fixed Wappai pixel style, preserves subject identity and requests a silhouette readable on round/rectangular device screens. Text creation remains available.
- Invalid/corrupt/tiny/transparent/blank references fail before creating jobs. Generated previews still require an explicit matching SHA-256 approval before building the existing 24-pose/43-sequence pack. Default Pips remain protected.
- Web has matching photo flow and confirmed conversation deletion. This change does not modify firmware or its sleep/render cadence.

## Signing limitation

The standard Push-enabled device build is blocked: Xcode has no configured developer account and its cached wildcard profile does not allow Push Notifications. The installed local build uses an isolated copy with an empty entitlement file; repository Push entitlements are unchanged. This local build does **not** support APNs. A developer account, explicit app identifier, Push-enabled profile and configured APNs backend are still required. This is not an App Store-ready distribution or a Push delivery test.

## Reproduction

Use Python 3.11+ with server dependencies and run `PYTHONPATH=server python -m pytest server/tests -q`. For UI tests, seed the isolated simulator using `xcrun simctl addmedia <simulator-id> server/sim/pixel-0-0.png`, then run the Piko scheme's tests. Browser tests use `tools/wappai/web_qa_server.py` and `tools/wappai/web_browser_test.py` with a fresh `QA_PORT`; set `QA_BROWSER=webkit` for WebKit. These fixtures must not point to personal deployment data.
